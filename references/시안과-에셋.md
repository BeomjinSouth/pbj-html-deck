# 시안과 에셋: 이미지 모델로 본보기를 뽑고 그림을 낱개로 만든다

`scaffold` 뒤에 `build "<덱>"`로 뼈대를 묶고 `check "<덱>" --shots`로 한 번 본 뒤에 읽는다. 그림을 만들기 전에는 자리표시 오류가 날 수 있다. 순서는 **마스코트 원화 한 장 → 장별 시안 → 나머지 에셋**이다.

- 원화는 덱의 캐릭터를 정한다. 뒤의 모든 그림이 이 한 장을 참고한다.
- 시안은 그 장의 뼈대 화면을 이미지 모델이 "완성된 한 장"으로 다시 그린 것이다. **구도와 분위기의 본보기**이고, 화면의 문법(카드·글꼴·색)은 부품이 정한다.
- 에셋은 시안 속 그림을 투명 배경의 낱개 그림으로 다시 뽑은 것이다. 구현에는 이것만 들어간다.

## 1. 명령

```
python "<스킬>/scripts/deck.py" art "<덱>" mascot
python "<스킬>/scripts/deck.py" art "<덱>" mockups
python "<스킬>/scripts/deck.py" art "<덱>" assets
```

| 명령·옵션 | 하는 일 |
| --- | --- |
| `mascot` | 콘티의 `mascot.look`으로 원화 `그림/<마스코트 id>.png`를 만든다 |
| `mockups` | 장마다 뼈대를 1920×1080으로 찍고(모든 단계가 나타난 모습) 그 캡처와 원화를 참고로 `시안/NN-<장 id>.png`를 만든다. `mockup: "same-as:<id>"`인 장은 건너뛴다 |
| `assets` | 원화를 뺀 콘티의 모든 에셋을 `그림/<에셋 id>.png`로 만든다. 포즈는 원화를, 그 그림이 그려진 시안이 있으면 그 시안도 참고한다 |
| `all` | 위 셋을 이어서 돌린다. 시안을 보지 않고 에셋까지 가므로 처음 만들 때는 나눠서 돌린다 |
| `--only id,…` | 그 id만. `mascot`에는 마스코트 id, `mockups`에는 장 id, `assets`에는 에셋 id를 쓴다. 콘티에 아예 없는 id면 멈춘다 |
| `--force` | 지시문과 참고 그림이 지난번과 같아도 다시 뽑는다 |
| `--jobs N` | 한꺼번에 돌릴 호출 수(기본 4) |
| `--dry-run` | 그리지 않고 지시문과 첨부 목록만 출력한다. `시안/prompts/<id>.txt`·`그림/prompts/<id>.txt`에도 남는다 |
| `--mode polish\|compose` | `mockups`의 참고 그림. 기본 `polish` |

실제로 걸린 시간(12장·에셋 10개 덱): 원화 50초, 시안 한 장 49~68초, 시안 10장을 `--jobs 5`로 2분 14초, 에셋 9개를 `--jobs 5`로 1분 43초. 호출 수는 원화 1 + 시안 12 + 에셋 10이 바닥이고, 시험과 다시 뽑은 것까지 33회였다.

만들어지는 파일: `시안/NN-<id>.png`(1920×1080), `그림/<id>.png`(스티커를 포함한 낱개 그림은 투명 여백을 다듬고 긴 변 최대 800px로 축소, 작은 원본은 확대하지 않음), 각 폴더 안의 원본 `raw/<id>/vNNN.png`, 기록 `manifest.json`, 모아보기 `_sheet.png`. 배경은 1920×1080 불투명 그림이다.

지시문과 참고 그림이 지난번과 같으면 `[id] 건너뜀 (프롬프트와 참고 그림이 같음)`으로 넘어간다. 원고나 부품을 바꿔 캡처가 달라진 장은 `mockups`가 다시 뽑는다. 한 장만 고쳤으면 `--only`를 쓴다.

### 두 모드

| | `polish`(기본) | `compose` |
| --- | --- | --- |
| 참고 그림 | 그 장의 뼈대 캡처 + 원화 | 부품 견본 화면(`assets/kit/board-<색 묶음>.png`) + 원화 |
| 써 본 결과 | 12장 모두 구도·글자·줄바꿈·그래프의 값이 뼈대 그대로였고, 점선 자리표시만 그림으로 바뀌었다 | 글자는 맞았지만 견주기 칩의 색이 달라졌고, 좌표평면의 직선을 지어 그렸고, 없는 단추·아이콘이 붙은 적이 있다 |
| 쓸 때 | 늘 이쪽 | 뼈대와 다른 배치를 일부러 구해 볼 때만. 구현의 기준으로 삼지 않는다 |

## 2. 시안을 뽑기 전에

시안은 캡처를 따라 그리므로 **뼈대의 흠도 그대로 옮긴다.** `check "<덱>" --shots`의 `sheet-NN.png`에서 글자·수식·줄바꿈을 먼저 확인하고 고친 뒤 시안을 뽑는다. `$y=-3x$`와 `$(-2,-4)$`의 음수 부호는 변환기가 숫자에 붙여 쓴다.

처음에는 두세 장만 뽑아 본다.

```
python "<스킬>/scripts/deck.py" art "<덱>" mockups --dry-run --only cover,quiz
python "<스킬>/scripts/deck.py" art "<덱>" mockups --only cover,quiz
```

`--dry-run`의 `Text on the slide` 목록이 화면에 보이는 글자와 같은지, `Illustrations` 줄이 그 장의 자리표시와 맞는지 본다. 정리 장에 여러 대사를 쓰면 `reveal: "all"`에서는 첫 대사, 단계 공개에서는 끝까지 펼친 캡처에 보이는 마지막 대사를 지시문에 적는다. 단계가 지나 가려지는 그림(차례 구도의 앞 단계 그림)과 맞음·틀림 때만 나오는 반응 포즈는 캡처에 없으므로 목록에도 시안에도 나오지 않는다. 그런 에셋은 시안을 화풍 참고로만 받는다.

## 3. 시안을 보는 법

`시안/_sheet.png`(3열, 장 순서)를 열고, 글자가 많은 장은 `시안/NN-<id>.png`를 따로 연다.

| 볼 것 | 다시 뽑아야 하는 경우 |
| --- | --- |
| 초점 | 콘티의 `focus`가 아닌 것이 가장 크다 |
| 구도 | 카드·줄·단추의 자리와 크기가 뼈대와 다르다. 화면이 잘렸다(`경고: 원본이 16:9가 아니어서…`) |
| 글자 | 콘티와 낱말·줄바꿈이 다르다, 한글이 깨졌다, 없는 글이 붙었다 |
| 그림 | 자리표시가 그대로 남았다, 목록에 없는 캐릭터가 있다, 마스코트가 원화와 다른 캐릭터다 |
| 수학 | 좌표평면의 눈금·점·직선이 뼈대와 다르다(시안의 도형은 증거가 아니다. 구현은 SVG가 그린다) |

```
python "<스킬>/scripts/deck.py" art "<덱>" mockups --only sort --force
```

원고를 고쳐서 다시 뽑는 것이면 캡처가 달라졌으므로 `--force` 없이 된다. 콘티의 `mockup_note`에 적은 말은 지시문 끝의 `extra direction`으로 들어간다(이번 덱에서는 쓰지 않고 통과했다).

실제로 다시 뽑은 것: 글자 한도에 걸려 콘티의 문구를 바꾼 장 1장(시안의 글자가 콘티와 달라졌으므로). 에셋을 넣은 뒤에 다시 뽑은 장에서는 끌어 담는 칸(점선 테두리)에 마스코트를 그려 넣은 적이 있어 지시문을 고쳤다. 숫자 `1`이 `I`처럼 그려진 칩 하나는 그대로 두었다(구현의 글자는 콘티에서 온다).

## 4. 에셋을 보는 법

`그림/_sheet.png`(남색 바탕이라 투명한 곳과 흰 테두리가 보인다)를 연다.

- 포즈마다 **같은 캐릭터**인가: 몸 색, 얼굴, 목도리 같은 소품이 원화와 같다.
- 배경이 투명한가: 캐릭터 둘레에 네모난 바탕이나 얼룩이 없다. `manifest.json`의 `bg_removed: "fallback"`은 투명 배경을 받지 못해 도구가 바탕을 지웠다는 뜻이니 테두리를 꼭 본다.
- 잘린 곳이 없는가: 머리·꼬리·소품이 끝까지 있다.
- 시안 속 그림과 같은 모습인가: 포즈, 소품, 보는 방향.

| 실제로 생긴 일 | 고친 방법 |
| --- | --- |
| 수조 그림에 눈·입이 생겼다(시안의 수조에는 없었다) | 지시문에 "사물에는 얼굴을 그리지 않는다"를 넣고 `--only scene_tank`로 다시 뽑았다. 지금은 기본 지시문에 들어 있다 |
| 낱개 그림을 큰 칸에 넣었더니 `check`가 `image-upscaled` 경고 | 표시 크기를 줄이거나 더 큰 원본을 쓴다. `sticker`와 `scene` 모두 후처리 시 긴 변이 최대 800px이므로 `kind`만 바꿔 다시 가져와도 커지지 않는다 |
| 반응 포즈(`mascot.yes`·`no`)는 어느 시안에도 없다 | 원화만 참고하고도 같은 캐릭터로 나왔다. 포즈 설명에 몸짓·표정을 다 적는다 |

잘 통한 그림 설명(영문, 한 줄): 포즈는 **소품 + 몸짓 + 표정**(`holding a big round magnifying glass up to one eye and leaning forward curiously`), 사물은 **무엇이 어떤 상태인지 + 넣지 않을 것**(`a rectangular glass water tank about half full of clear blue water, … ; no measuring marks`). 고친 설명은 콘티에 쓰고 `plan`을 다시 통과시킨 뒤 `art "<덱>" assets --only <id>`.

## 5. 이미지 생성을 쓸 수 없을 때

`codex` 명령이 없거나 중첩 호출이 막힌 환경에서는 직접 만든 그림을 같은 후처리와 기록으로 넣는다.

```
python "<스킬>/scripts/deck.py" art "<덱>" import mascot "<원화 파일>"
python "<스킬>/scripts/deck.py" art "<덱>" import mascot_wave "<포즈 파일>"
python "<스킬>/scripts/deck.py" art "<덱>" import mockup:cover "<시안 파일>"
```

- 에셋 id는 콘티에 있어야 한다. 낱개 그림은 여백을 다듬어 줄이고, 시안은 1920×1080으로 맞춘다(가운데를 남기고 자른다).
- 가져온 그림도 3·4절대로 본다. **자리표시가 남은 채로 전달하지 않는다**(`check`가 `placeholder-left` 오류로 막는다). 그림을 구할 수 없는 에셋은 콘티에서 빼거나 그 자리를 SVG(`draw`)로 바꾼다.

## 6. 통과 조건과 처방

`status`의 **시안 ✓**: `그림/<마스코트 id>.png`가 있고 모든 장의 `시안/NN-<id>.png`가 있다(`same-as` 장은 가리키는 장의 시안). **에셋 ✓**: `그림/manifest.json`의 모든 항목이 `ok`이고 콘티의 모든 에셋 id가 들어 있다. 에셋 ✓는 그림 파일의 존재나 최신성을 따로 확인하지 않는다. 3·4절을 눈으로 본 것까지가 통과다.

| 메시지 | 처방 |
| --- | --- |
| `codex 명령을 찾을 수 없습니다` | Codex CLI가 없는 환경이다. 5절의 `import` |
| `[id] 실패: 이미지가 생성되지 않았습니다. …` | 뒤에 붙은 까닭을 읽고 그 id만 `--only`로 다시 |
| `앞선 생성 실패로 호출을 중단했습니다` | 두 번 잇달아 실패했거나 로그인·연결 오류다. 까닭을 고친 뒤 같은 명령을 다시 돌린다(된 것은 건너뛴다) |
| `없는 --only id: …` | 장 id·에셋 id의 철자를 콘티에서 확인한다 |
| `경고: [id] 없는 참고 그림은 빼고 진행합니다: …` | 원화나 시안을 아직 안 만들었다. `mascot` → `mockups` → `assets` 순서를 지킨다 |
| `경고: 원본이 16:9가 아니어서(…) 가장자리가 잘렸습니다` | 그 시안을 열어 잘린 곳을 보고, 내용이 잘렸으면 `--force`로 다시 |
| `경고: 배경 제거 후에도 투명 비율이 3% 미만입니다` | 배경이 남았다. `--force`로 다시 뽑는다 |
| 에셋이 ✗인데 그림은 다 있다 | `manifest.json`에 `status: "fail"`인 항목이 남았다. 그 id를 다시 뽑거나 `import`한다 |
