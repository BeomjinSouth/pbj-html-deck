# 대조와 마감

`check`가 오류 0이 된 뒤에 읽는다. 순서는 **대조 → 비평 한 번 → 다듬기 한 번 → 독립 검수**다. 여기를 통과하지 못한 덱은 전달하지 않는다.

## 1. 대조: 시안과 구현을 나란히 본다

```
python "<스킬>/scripts/deck.py" compare "<덱>"
```

- `검사/compare-NN.png` — 왼쪽이 시안, 오른쪽이 지금 구현(모든 단계가 나타난 모습).
- 표의 점수는 **볼 순서**다. 낮은 장부터 연다. 점수가 높다고 통과가 아니고 낮다고 실패도 아니다(시안은 그림이라 글자 결·그림 결이 달라 점수는 늘 깎인다).
- **모든 장의 compare 그림을 한 장씩 직접 연다.** 모아보기만 보고 쓰지 않는다.

`compare`가 처음 한 번 `검사/대조.md` 틀을 만든다(이미 있으면 건드리지 않는다). 장마다 한 줄을 채운다. 줄에는 그 장의 번호와 id가 있어야 한다.

| 칸 | 묻는 말 |
| --- | --- |
| 구도 | 큰 덩어리들의 자리와 크기 비율이 같은가. 읽는 순서(제목 → 핵심 → 보조)가 같은가 |
| 글자 | 제목과 핵심 문구의 크기 서열, 줄 나눔, 강조한 낱말이 같은가 |
| 색·모양 | 바탕·카드·강조색, 외곽선·그림자·모서리가 같은 식인가 |
| 그림 | 시안의 그림이 모두 있고 자리·크기·포즈가 같은가 |
| 연출 | 콘티의 단계·상호작용이 들어 있고 동작하는가(`검사/state-NN.png`) |

칸마다 다섯 낱말 중 하나만 쓴다: `일치` · `조정(까닭)` · `빠짐` · `다름` · `덧붙음`.

**조정으로 인정하는 까닭은 넷뿐이다.**

1. 시안의 글자가 콘티와 다르다 → 콘티가 옳다.
2. 시안의 도형·수·그래프가 수학적으로 틀렸다 → 정확한 쪽이 옳다.
3. 시안대로 하면 학생이 읽는 문장·그래프 눈금·축 이름 등이 32px보다 작아지거나 쪽 번호·저작 표시 같은 보조 글자가 26px보다 작아진다.
4. 시안대로 하면 누를 자리가 모자라거나 내용이 캔버스를 넘는다.

`빠짐`·`다름`·`덧붙음`이 하나라도 있는 장은 판정 `고침`이다. `원고.html`을 고치고 `build → check → compare`를 다시 돈다. 모든 장이 `일치`·`조정`뿐이면 파일 맨 아래에 `최종: 통과`를 적는다.

시안 그림을 장에 통째로 붙여 넣어 점수를 올리는 것은 금지다(`slide-is-image` 오류로 잡힌다). 시안은 목표 화면이고 재료가 아니다.

## 2. 바닥선: 장마다 예/아니오

한 장씩 실제 화면(`검사/slide-NN.png`, 상호작용은 `state-NN.png`)을 보며 답한다. 해당 없는 것은 `-`. **'아니오'는 모두 고친다.**

**한눈에**

1. 3초 안에 콘티의 `focus`가 가장 먼저 눈에 들어오는가?
2. 이 장의 한 가지 할 일(`purpose`)과 상관없는 요소가 눈길을 다투지 않는가?
3. 한꺼번에 보이는 새 정보·선택지가 4개 이하인가? (넘으면 단계로 나누거나 장을 가른다)
4. 관계있는 글과 그림은 붙어 있고, 다른 묶음과는 떨어져 있는가?

**글자**

5. 제목 → 핵심 → 보조의 크기·굵기 차이가 뚜렷한가? (비슷한 크기 셋이 나란하면 '아니오')
6. 본문 기본이 46px이고 학생이 읽는 글자(문장, 그래프의 눈금·축 이름 포함)는 32px 이상, 쪽 번호·저작 표시 같은 보조 글자는 26px 이상인가? 검사는 26px 미만만 잡으므로 32px은 따로 확인한다.
7. 글자와 수식이 상자·가장자리에서 잘리지 않고, 줄 나눔이 뜻 단위를 끊지 않는가?
8. 글자와 바탕의 대비가 넉넉한가? (옅은 색 바탕 위 흰 글자, 노랑 위 흰 글자는 '아니오')
9. 메이플스토리 글꼴로 그려지고 네모(□)로 빠진 글자가 없는가?

**그림**

10. 그림이 하나 이상 있고(구분장 제외) 내용과 관계가 있는가?
11. 그림의 비율이 찌그러지지 않고 흰 테두리·투명한 곳이 깨끗한가?
12. 그림이 질문·수식·답을 가리지 않는가?
13. 수학 도형·그래프가 정확한가? (길이 비, 각, 좌표, 눈금 — 이미지 모델이 그린 도형을 증거로 삼지 않는다)

**순서와 연출**

14. 생각할 시간이 필요한 장에서 답이 먼저 보이지 않는가?
15. 단계 공개가 설명의 순서와 맞고, 한 번에 나타나는 양이 한 덩어리인가?
16. 움직임이 뜻이 있는 곳(등장·정답 반응)에만 있고 서로 다투지 않는가?

**누르는 것**

17. 누를 수 있는 것이 누를 수 있어 보이고, 못 누르는 것과 구별되는가?
18. 맞음·틀림이 색만이 아니라 모양·기호(✓, ✕, 테두리)로도 구별되는가?
19. 틀린 뒤에 다시 해 볼 수 있고, 다음에 무엇을 할지 화면에서 알 수 있는가?
20. 단추의 글자가 결과를 말하는가? (`확인`, `다시`, `뒤집기` — `클릭`, `여기`는 '아니오')

자동 검사가 조용하다고 위 항목이 '예'인 것은 아니다. 뒷자리에서 읽히는지는 캡처를 25% 크기로 줄여 보고 판단한다.

## 3. 비평 한 번, 다듬기 한 번

덱 전체를 두고 **한 번씩만** 한다. 끝없이 돌지 않는다.

**비평.** `검사/sheet-NN.png`(모아보기)를 열고 덱 전체를 한 벌로 본다.

| 볼 것 | '아니오'의 신호 |
| --- | --- |
| 흐름 | 열기 → 탐구 → 확인 → 정리의 굴곡 없이 같은 구도가 이어진다 |
| 리듬 | 글만 있는 장, 그림만 있는 장이 몰려 있다. 상호작용이 한쪽에 몰려 있다 |
| 한 초점 | 장마다 가장 큰 것이 둘 이상이다 |
| 작업 기억 | 앞 장의 조건을 외워야 풀 수 있는데 이 장에 다시 적혀 있지 않다 |
| 일관성 | 같은 뜻의 것(단추, 정답 표시, 단계 표시)이 장마다 모양이 다르다 |
| 마스코트 | 같은 포즈만 나온다. 말풍선이 제목을 되풀이한다 |
| 말 | 학생이 모르는 낱말, 번역투, 긴 문장이 있다 |
| 군더더기 | 지워도 뜻이 그대로인 장식·글이 있다 |

나온 문제를 중요한 순서로 적는다(장 번호 · 무엇이 · 어떻게).

**다듬기.** 비평의 문제와 2절의 '아니오'를 한 번에 고친다. 지킬 것:

- 부품의 변수와 구도의 선택지 안에서만 고친다. **새 색·새 글꼴·새 구도를 발명하지 않는다.**
- 사실·수치·콘티의 문구를 바꿔야 하면 `콘티.json`부터 고친다. `plan-mismatch`는 장·구도·상호작용을 비교하며 문구 차이까지는 잡지 않는다.
- 고친 뒤 `build → check → compare`.

임페커블 스킬을 쓸 수 있으면 `$impeccable critique`·`$impeccable polish`의 관점을 빌려도 된다. 다만 임페커블은 웹 화면 기준이라 4절의 차이를 먼저 읽는다. 임페커블의 관문을 통과했다고 적지 않는다(이 덱의 관문은 이 문서다).

## 4. 임페커블 원문과 다르게 두는 것

| 임페커블 원문 | 이 덱 | 까닭 |
| --- | --- | --- |
| 제목 위 작은 표시(eyebrow) 금지 | `탐구 1` 같은 **단계 표시는 둔다** | 수업에서 지금 어디인지 알려 주는 길잡이다 |
| 딱딱한 오프셋 그림자 금지 | 카드·단추의 딱딱한 그림자는 **이 덱의 세계** | 스티커 팝 방향을 사용자가 골랐다 |
| 그림을 SVG로 흉내 내지 않기 | 캐릭터·사물은 생성 그림, **수학 도형·그래프는 SVG** | 길이·각·좌표가 정확해야 한다 |
| 동작 줄이기(reduced motion) 대안 | 넣지 않는다 | 교실 화면에서 늘 같은 연출이어야 한다 |
| 본문 폭 65~75자, 16px 바닥 | 본문 기본 46px, 문장 32px 이상·보조 글자 26px 이상, 장당 한 메시지 | 뒷자리에서 읽는 화면이다 |
| 같은 크기 카드의 반복 금지 | 견줄 것 2~4개는 같은 크기 카드가 옳다 | 견주기가 목적이다 |
| 장식 격자 바탕 금지 | 옅은 점 바탕, 좌표평면·모눈은 둔다 | 방향의 일부이고 수업 내용이다 |

`check`는 임페커블 지적이 부품·엔진에서만 나온 경우 숨기고, 작성자가 같은 스타일을 썼거나 출처를 가를 수 없으면 `imp-…`로 보여 준다. 부품에서만 나온 임페커블 `low-contrast`를 숨겨도, 실제 화면에서 3:1 미만인 단색 글자 대비는 `deck.audit`가 별도 `low-contrast`로 검사한다.

## 5. 독립 검수와 `마감.md`

독립 검수는 **제작 대화를 물려받지 않은 새 에이전트**에게 맡긴다. Codex에서 하위 에이전트를 띄울 때는 `fork_turns: "none"`으로 대화 기록을 넘기지 않는다. 검수자에게는 아래 브리프와 덱 폴더 경로만 준다(네 해석·변명을 붙이지 않는다).

> 이 폴더의 HTML 수업 슬라이드를 검수한다. `콘티.json`(장마다 `purpose`=청중이 할 일, `focus`=가장 먼저 보일 것), `검사/compare-NN.png`(왼쪽 시안·오른쪽 구현), `검사/slide-NN.png`(각 장), `검사/state-NN.png`(상호작용을 푼 화면), `검사/sheet-NN.png`(모아보기)를 **모두 열어 본다.** `<스킬>/references/대조와-마감.md`의 2절 스무 항목과 3절 비평 표로 장마다 판정하고, 수학 내용(정답·도형·그래프)은 직접 계산해 확인한다. 결과를 아래 형식으로만 쓴다. 고치지는 않는다.

`검사/마감.md`의 형식. **첫 줄은 `판정: ` 뒤에 `통과`·`고침`·`다시`·`증거 부족` 중 하나만** 쓴다(다른 글자를 붙이면 `status`가 읽지 못한다). 둘째 줄 `검수:`는 제작 대화를 물려받지 않은 새 에이전트가 봤으면 `독립`, 대화를 물려받은 에이전트가 봤거나 직접 봤으면 `자체`로 적는다(자체 검수는 전달할 때 사용자에게 밝힌다).

```
판정: 통과
검수: 독립
본 것: compare 12장, slide 12장, state 5장, sheet 1장
고칠 것:
- 7번 장 · 마스코트가 보기 D를 가린다 · 마스코트 칸을 줄인다
남긴 경고와 까닭:
- 13번 장 image-upscaled · 원본이 800px라 1.4배로 보이지만 눈으로 흐리지 않음
확인하지 못한 것:
- 터치 화면에서의 끌어 놓기
```

- `판정: 고침` — ‘고칠 것’을 고치고 `build → check → compare` 뒤 다시 검수받는다.
- `판정: 다시` — 여러 장이 시안과 구도부터 다르다. 그 장들을 `scaffold --only … --force`로 다시 세우고 구현부터 다시 한다.
- `판정: 증거 부족` — 빠진 그림·캡처를 채운다(`art`, `check --shots`, `compare`).
- **두 번까지** 돈다. 그래도 통과가 아니면 남은 지적을 그대로 사용자에게 알린다. 검수자의 판정을 손으로 `통과`로 바꾸지 않는다.
- 제작 대화를 물려받지 않은 새 에이전트를 쓸 수 없으면 캡처를 처음 보는 사람처럼 한 장씩 다시 열어 같은 형식으로 쓰고 `검수: 자체`로 적는다.

`대조.md`는 최신 `compare.json`보다, `마감.md`는 최신 `대조.md`와 `report.json` 둘보다 나중에 쓴 것이어야 한다. `build`를 다시 하면 검사·대조·마감을 모두 새로 통과해야 한다.
