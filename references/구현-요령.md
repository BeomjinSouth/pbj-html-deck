# 구현 요령: 시안에 맞추고 검사를 통과시킨다

`scaffold`가 만든 `원고.html`은 이미 구도·글꼴·색이 맞는 화면이다. 구현 단계의 일은 **새로 만드는 것이 아니라 시안과 다른 곳을 좁히는 것**이다. 고친 뒤에는 `build` → `check --shots`로 확인한다.

## 1. 원고의 모양

```html
<section class="slide" data-id="meet" data-layout="cards">
  <header class="hd">…<h2>막대 끝이 <b class="hl">만날까?</b></h2></header>
  <div class="main">…</div>
  <figure class="buddy">…<img class="asset" data-asset="mascot_point" src="그림/mascot_point.png" alt="…"></figure>
</section>
```

- `data-id`·`data-layout`은 콘티와 장을 짝짓는 표다. 바꾸지 않는다.
- 클래스 이름은 부품의 것이다. 구조(요소의 순서·중첩·클래스)를 손으로 바꾸면 모양이 깨진다. **구조를 바꿔야 하면 콘티를 고치고 `scaffold "<덱>" --only <id> --force`로 그 장만 다시 만든다**(그 장에 손으로 넣은 수정은 사라지니 다시 만든 뒤에 다듬는다).
- `is-*` 클래스, `data-waiting`·`data-gone`·`data-mood`는 엔진이 붙였다 뗀다. 원고에 쓰지 않는다.

## 2. 시안에 맞추는 순서

`compare`가 만든 `검사/compare-NN.png`(왼쪽 시안, 오른쪽 구현)를 장마다 열어 아래 순서로 본다. 위에서부터 고치면 아래는 대개 따라 맞는다.

1. **읽는 순서와 초점** — 시안에서 가장 먼저 보이는 것이 구현에서도 그런가. 다르면 글이 많거나 구도가 맞지 않은 것이다 → 콘티로 돌아간다.
2. **그림의 크기와 자리** — 마스코트·스티커가 시안만큼 크고 그 자리에 있는가(3절의 손잡이).
3. **줄바꿈과 강조** — 제목이 시안과 같은 곳에서 끊기는가(콘티의 `\n`), 강조한 낱말이 같은가(`**…**`).
4. **색** — 단계 표시의 색, 카드의 색 면이 시안과 같은 계열인가(4절).
5. **손맛** — 시안에 있는 반짝임·기울기가 장의 인상에 꼭 필요하면 스티커 에셋으로 더한다(CSS로 그리지 않는다).

시안이 부품과 다르게 그린 것(카드 모양이 다르다, 없는 장식이 있다)은 **부품을 따른다.** 시안은 구도와 분위기의 본보기이고, 화면의 문법은 부품이 정한다. 시안의 글자가 콘티와 다르면 콘티가 맞다.

## 3. 손잡이: 고쳐도 되는 것

| 하려는 일 | 방법 |
| --- | --- |
| 마스코트 칸을 넓히거나 좁힌다 | 그 장의 `<section … style="--buddy-w:520px">`(기본 430px) |
| 그림 하나를 키우거나 옮기거나 기울인다 | 그 `img`에 `style="scale:1.15; translate:20px -12px; rotate:-4deg"`(브라우저 편집과 같은 방식이라 나중에 사용자가 다시 고칠 수 있다) |
| 제목의 줄을 나눈다 | 콘티의 `\n`. 원고에서는 `<br>` |
| 낱말을 강조한다 | `<b class="hl">낱말</b>` — 한 제목에 한 군데 |
| 나타나는 순서를 바꾼다 | `data-step="N"`(같은 수는 함께). 콘티의 `"reveal": "all"`은 틀의 단계 공개를 없애지만 일부 그림·대사 전환은 남으므로 화면을 확인한다 |
| 나타날 때의 효과 | `data-in="pop\|rise\|drop\|left\|right\|zoom\|fade"`(SVG 선은 `draw`). 한 장에 한두 군데만 |
| 그림을 눌러 크게 본다 | 그 칸에 `data-zoom` |
| 여백이 뜻인 장(큰 글 하나)의 빈 공간 경고를 끈다 | `<section … data-roomy>` — 정말 뜻한 여백일 때만 |
| 캔버스 밖으로 일부러 나가는 장식 | 그 요소에 `data-bleed` |
| 그림 위에 일부러 얹은 글자 | 그 글자 칸에 `data-over` |

**하지 않는 것:** 글자 크기를 px로 직접 주기(부품의 크기 위계가 무너진다 — 글이 많으면 줄인다), 새 색 값 쓰기(토큰만: `var(--coral)` `--yellow` `--mint` `--sky` `--violet` `--ink` `--accent`), `.slide` 자체에 `position`·`width`·`height`·`transform`·`overflow` 주기, `position:fixed`, `vw`·`vh`, 외부 자원.

## 4. 덱 전용 CSS·스크립트

꼭 필요할 때만 원고의 `<head>`에 `<style>`을 둔다. 선택자는 `.slide[data-id="…"]` 아래로, 평평하게(중첩·`@import` 없이), 길이는 px(캔버스 기준), 색은 토큰으로 쓴다. `check`의 임페커블 지적(`imp-…`)이 나오면 덱 전용 스타일·스크립트·인라인 스타일·추가 마크업을 확인한다. 부품·엔진에서만 나온 것으로 확인된 지적은 숨기고, 작성자 쪽에도 있거나 출처가 불분명하면 보여 준다.

스크립트는 조작 탐구에 덱 전용 그리기가 필요할 때만 쓴다: `deck.lab('[data-id="lab"] [data-lab]', (state, root) => { … })`. 실행 중에 만든 요소에는 `data-runtime`을 붙인다(저장할 때 빠진다). 장 이동은 `deck.on('slidechange', fn)`.

## 5. 직접 그리는 그림(SVG)과 조작 탐구

- 수학 도형은 `draw`·`stage` 필드에 SVG로 쓴다. 클래스와 좌표 계산법은 [수학 표기와 도형](수학-표기와-도형.md).
- 조작 탐구의 `data-bind`·`data-show`·`data-if`, 그래프의 `data-fn`·`data-pt`는 [콘티 쓰기 5절](콘티-쓰기.md). 조절기를 직접 최솟값·최댓값으로 옮겨 두 화면을 확인한다. `check`의 `state-NN.png`는 자체 시험이 마지막으로 남긴 상태다. 그림이 칸을 넘으면 `viewBox`를 넓힌다.
- 위젯의 원고 약속(속성 이름, 상태 클래스)은 [구조와 계약](구조와-계약.md)의 위젯 표에 있다. 틀이 이미 맞게 써 두었으니 속성을 지우거나 옮기지 않는다.

## 6. 검사 메시지와 처방

`check "<덱>" --shots`는 장마다 모든 단계를 나타낸 화면을 재고(`sheet-NN.png`, `slide-NN.png`), 상호작용을 실제로 눌러 본다(`state-NN.png`). 일부 장만 다시 볼 때는 `--slides 3,7`(모아보기는 `part-NN.png`). 마지막 검사는 전체로 한다.

| 메시지(code) | 뜻 | 처방 |
| --- | --- | --- |
| `overflow-canvas` · `text-clipped` · `math-overflow` | 글·수식이 넘치거나 잘림 | 글을 줄이거나 장을 나눈다. 수식은 줄을 나눈다 |
| `text-overlap` · `text-on-image` | 함께 보일 수 있는 글끼리, 글과 그림이 겹침 | 글이나 그림을 옮기거나 줄인다(3절). 그림 위의 뜻한 글에는 `data-over` |
| `small-text` | 26px보다 작은 글자 | 글을 줄여 큰 글자로. 학생이 읽는 문장·그래프 눈금·축 이름은 32px 이상, 쪽 번호·저작 표시 같은 보조 글자는 26px 이상인지 따로 확인한다. 그래프에서 `font`를 직접 줬다면 크기와 SVG 배율도 확인한다 |
| `edge-crowding` | 글자가 가장자리 56px 안 | 옮긴 요소를 안쪽으로 |
| `near-miss` | 나란한 것이 2~10px 어긋남 | 손으로 옮긴 `translate`를 맞추거나 지운다 |
| `empty-space` | 화면의 35%도 안 찼거나 아래가 빔 | 그림을 키우거나 내용을 더한다. 뜻한 여백이면 `data-roomy` |
| `text-heavy` | 보이는 글자 90자 초과 | 장을 나누고 설명은 `talk`로 |
| `no-visual` | 그림·도형·위젯이 없음 | 에셋이나 그림을 더한다 |
| `placeholder-left` | 에셋 파일이 없음 | `art "<덱>" assets`(또는 `--only <id> --force`) |
| `image-upscaled` | 그림을 1.4배 넘게 키움 | 표시 크기를 줄이거나 더 큰 원본을 쓴다. 낱개 에셋은 `scene`도 최대 800px이므로 종류만 바꿔서는 커지지 않는다 |
| `image-distorted` | 그림 비율이 틀어짐 | `width`·`height`를 함께 주지 않는다(`scale`을 쓴다) |
| `slide-is-image` | 그림 한 장이 화면을 덮음 | 시안을 붙여 넣은 것. 지우고 구도로 만든다 |
| `low-contrast` | 글자와 바탕의 대비 부족 | 바꾼 색을 되돌린다 |
| `font-fallback` | 글꼴에 없는 글자 | 특수 기호를 흔한 글자로 바꾼다 |
| `plain-math` | `^`, `<=` 같은 날것 수식 | 콘티에서 `$…$`로 쓴다 |
| `widget-invalid` | 위젯 구조가 틀림(정답 없는 문제 등) | 콘티의 그 장 필드를 고쳐 `scaffold --only … --force` |
| `widget-broken` | 눌러 봤는데 동작하지 않음 | 위젯을 가린 요소(옮긴 그림 등)를 치운다. 구조를 손으로 바꿨으면 되돌린다 |
| `plan-mismatch` | 콘티의 장·구도·상호작용이 결과에 없음 | `scaffold`로 빠진 장을 넣고 다시 묶는다. 글자 내용이 같은지는 따로 확인한다 |
| `console-error` | 브라우저의 스크립트·콘솔 오류 | 오류 내용과 식의 변수 이름을 확인한다 |
| `imp-…` | 임페커블의 지적 | 지적 원문이 가리키는 원고·스타일을 확인한다. 부품이나 엔진에서 온 경고도 남을 수 있다 |

오류는 0이 될 때까지 고친다. 경고는 고치는 것이 기본이고, 남길 때는 `검사/마감.md`에 까닭을 한 줄 적는다.

## 7. 눈으로 볼 것

`check`가 통과해도 `sheet-NN.png`를 처음부터 끝까지 넘겨 본다.

- 장마다 가장 먼저 눈에 들어오는 것이 그 장의 `focus`인가.
- 마스코트가 장마다 같은 캐릭터로 보이고, 포즈가 그 장의 일과 맞는가.
- 답이 질문보다 먼저 보이지 않는가(확인 구도의 처음 화면에 정답 표시가 없는가).
- 도형이 뜻한 모양(직각·평행·길이 비)으로 보이고, 그래프가 계산한 점을 지나는가.
- 같은 구도의 장들이 서로 같은 자리·같은 크기로 보이는가.
