# 콘티 쓰기

`콘티.json`은 덱의 단일 원본이다. 여기서 정한 것(장의 목적·구도·글·그림 목록)이 뼈대·시안·에셋·검사의 기준이 된다. **화면을 꾸미는 일이 아니라 수업을 설계하는 일이다.** 디자인은 구도가 이미 갖고 있다.

```
python "<스킬>/scripts/deck.py" new "<덱>" --title "세 막대로 삼각형 만들기" --kind lesson
python "<스킬>/scripts/deck.py" layouts            # 구도 29가지 한눈에
python "<스킬>/scripts/deck.py" layouts quiz,lab   # 그 구도의 필드·한도·복사해 쓸 조각
python "<스킬>/scripts/deck.py" plan "<덱>"        # 검사 (오류 0이 될 때까지)
```

## 1. 쓰는 순서

1. **`meta`를 먼저 채운다.** `goal`은 끝났을 때 청중이 **할 수 있는 것**(“…을 설명할 수 있다”), `message`는 덱 전체를 한 문장으로 줄인 것. 이 두 줄이 흐려지면 장이 늘어난다.
2. **흐름을 장 제목만으로 적어 본다.** 수업이면 `열기(표지 → 목표 → 발문) → 탐구·설명 → 확인 → 정리`, 연수면 `왜 → 무엇 → 어떻게 → 해 보기 → 정리`. 8~24장.
3. **장마다 `purpose`와 `focus`를 쓴다.** `purpose`는 이 장에서 청중이 **할 일** 한 문장(“세 경우를 견주어 본다”). `focus`는 화면에서 **가장 먼저 눈에 들어와야 할 것** 한 가지(“세 그림의 차이”). 둘을 쓰고 나면 구도가 정해진다.
4. **구도를 고르고 글을 채운다.** 아래 표에서 고르고 `layouts <이름>`으로 필드와 한도를 확인한다. 글은 한도 안에서 쓴다.
5. **그림을 정한다.** 마스코트 포즈와 스티커를 `assets`에 적는다(4절).
6. `plan`을 돌려 오류를 0으로, 경고는 까닭이 분명한 것만 남긴다.

## 2. 구도 고르기

| 하려는 일 | 구도 | 비고 |
| --- | --- | --- |
| 덱을 연다 | `cover` | 첫 장은 반드시 이것 |
| 오늘의 목표 2~4개 | `goals` | 누르면 체크된다 |
| 오늘의 흐름 | `agenda` | 지금 단계에 마스코트 |
| 생각을 여는 질문 하나 | `ask` | 큰 글자. 타이머를 달 수 있다 |
| 단원·활동이 바뀐다 | `section` | 색 바탕에 큰 번호 |
| 꼭 기억할 한 문장 | `point` | 노란 바탕 |
| 나란히 견줄 것 2~4개 | `cards` | 그림 + 이름 + 한 줄 |
| 순서가 있는 설명 | `steps` | 단계마다 그림이 바뀐다 |
| 둘을 견준다(된다/안 된다, 전/후) | `compare` | VS는 둘째 카드와 함께 나타난다 |
| 그림 하나를 크게 | `show` | 누르면 화면 가득 |
| 예제 풀이 | `example` | 문제 → 풀이 줄 → 답이 차례로 |
| 값을 표로 | `table` | 2~5열 × 2~5줄 |
| 같은 틀의 내용 2~4개 | `tabs` | 골라 본다 |
| 모둠·짝 활동 안내 | `activity` | 할 일 + 큰 타이머 |
| 값을 바꾸며 관찰 | `lab` | 슬라이더 → 그림이 따라 바뀜 |
| 그래프를 움직여 본다 | `graph` | 좌표평면 자동, 곡선·점 |
| 낱말·물음 → 뜻·답 | `flip` | 카드를 뒤집는다 |
| 짧은 보기 고르기 | `quiz` | 2~4지선다 |
| 문장 보기 고르기 | `quiz-long` | |
| 맞다/아니다 | `ox` | |
| 여러 개를 2~3묶음으로 | `sort` | 끌어 담기 |
| 차례 맞추기 | `order` | |
| 낱말과 설명 잇기 | `match` | |
| 말한 뒤 답 열기 | `reveal` | 가리개를 눌러 연다 |
| 수·낱말로 답하기 | `input` | 자동 채점 |
| 내 말로 쓰기 | `write` | 빈칸 문장틀, 타이머 |
| 발표자 뽑기 | `pick` | 번호·이름 무작위 |
| 오늘 알게 된 것 | `summary` | 말풍선·다음 시간 띠가 마지막 정리 줄과 함께 나타난다. `reveal: "all"`이면 처음부터 모두 보이고 첫 대사만 보인다 |
| 끝인사·다음 준비물 | `closing` | 마지막 장은 `summary`나 이것 |

**고를 때의 규칙**

- 같은 구도를 세 장 잇지 않는다. 설명 구도 두세 장 뒤에는 `ask`·`section`·확인 구도로 호흡을 바꾼다.
- 그림 없는 장을 두 장 잇지 않는다.
- **수업·연수는 상호작용 구도 사이가 5장을 넘지 않게, 종류는 2가지 이상.** 설명한 직후에 그 내용을 확인하는 구도를 둔다(설명 → `quiz`/`ox`/`sort`…). 덱 끝에 문제를 몰아 두지 않는다.
- 조작해 봐야 알 수 있는 것(값이 바뀌면 모양이 어떻게 달라지나)은 `cards`로 세 경우를 늘어놓지 말고 `lab`·`graph`로 직접 움직이게 한다.
- 한 장에 넣을 것이 한도를 넘으면 장을 나눈다. 구도를 바꿔 욱여넣지 않는다.

## 3. 모든 장에 쓸 수 있는 필드

| 필드 | 뜻과 쓰는 법 |
| --- | --- |
| `id` | 소문자·숫자·하이픈. 파일 이름에 쓰인다(`intro`, `quiz-1`) |
| `layout` | 구도 이름 |
| `purpose` · `focus` | 위 1절. 화면에는 나오지 않지만 시안 지시문에 들어간다 |
| `title` | 질문이나 결론으로. “삼각형의 조건”보다 “막대 끝이 **만날까?**” |
| `tag` | 수업 단계 표시(“탐구 1”, “확인”). **같은 글자는 같은 색**이 되니 단계 이름을 덱 전체에서 일관되게 쓴다 |
| `mascot` | 이 장의 마스코트 포즈(에셋 id). 구도에 자리가 있을 때만(`layouts`의 ‘마스코트 자리’) |
| `say` | 마스코트와 함께 쓰는 말풍선 대사 배열. 개수와 글자 한도는 `layouts <구도>`에서 확인한다. 일반 말풍선은 다음을 누를 때마다 바뀌고, `quiz`·`quiz-long`·`ox`·`sort`·`order`·`input`은 첫 대사만 쓴 뒤 정오 반응을 보인다. 화면의 글을 되풀이하지 말고 **볼 곳을 짚거나 한마디 거든다**(“가장 긴 막대를 봐!”) |
| `reveal` | `step`(기본: 단계별 공개) · `all`(틀의 단계 공개를 한꺼번에). 일부 구도의 그림·대사 전환은 별도 단계가 남으므로 실제 화면을 확인한다 |
| `talk` | 교사 발문·진행 메모. 화면에 넣지 않고 `진행안.md`로 나온다. 설명하고 싶은 말은 여기에 |
| `mockup_note` | 시안에 줄 연출 지시(영문 한두 문장, 선택) |
| `mockup` | `same-as:<id>` — 그 장의 시안을 함께 쓴다(같은 구도가 이어질 때) |

### 글자 안 표시

| 쓰기 | 화면 |
| --- | --- |
| `**낱말**` | 강조(제목에서는 형광 붓). **한 제목에 한 군데만** |
| `*x*` | 수학 변수(기울임) |
| `$6 < 3 + 4$` | 수식. `\frac{}{}` `\sqrt{}` `^{}` `_{}` `\times \div \le \ge \ne \angle \triangle \overline{AB}` 등 중학교 범위. 대문자는 정체(점·도형 이름), `-`는 `−`로 바뀐다 |
| 줄바꿈 `\n` | 줄 나눔. 뜻이 끊기는 곳에서 직접 나눈다 |
| `[[답]]` | 눌러서 여는 빈칸 |
| `{식}` `{식:1}` | 조작 값(`state`가 있는 `lab`·`graph` 장에서만). 수식 안에서는 `\val{식}` |

글자 수는 한글 1, 공백 0.5, 영문·숫자는 글자 폭에 따라 약 0.3~1.1로 센다.
수식은 보이는 폭으로 센다. 숫자 1개는 약 0.7, `=`는 양옆 간격까지 약 1.7이며 분수와 첨자는 겹치는 폭을 반영한다. 수식 하나가 한 줄 한도보다 길면 여러 줄 칸에서도 오류이므로 식을 나눈다.

## 4. 그림 목록 (`mascot`, `assets`)

```json
"mascot": { "id": "mascot", "name": "세모", "look": "a cute chubby orange fox cub with a teal scarf",
            "yes": "mascot_cheer", "no": "mascot_oops" },
"assets": [
  { "id": "mascot_wave",  "kind": "mascot",  "prompt": "waving one paw, big smile", "alt": "손 흔드는 세모" },
  { "id": "mascot_think", "kind": "mascot",  "prompt": "one paw on chin, looking up, thinking", "alt": "생각하는 세모" },
  { "id": "mascot_cheer", "kind": "mascot",  "prompt": "jumping with both paws up, confetti", "alt": "기뻐하는 세모" },
  { "id": "mascot_oops",  "kind": "mascot",  "prompt": "tilting head, puzzled but friendly", "alt": "갸웃하는 세모" },
  { "id": "sticks",       "kind": "sticker", "prompt": "three colorful wooden sticks of different lengths", "alt": "막대 세 개" }
]
```

- `mascot.look`은 영문 외형 묘사 한 줄(동물·사물 + 색 + 소품 하나). 주제와 이어지면 좋다(삼각형 수업의 ‘세모’). 실존 캐릭터·상표를 본뜨지 않는다.
- `kind`: `mascot`(포즈 — 원화를 자동으로 참고한다) · `sticker`(사물 하나) · `scene`(여러 사물 묶음, 큰 그림용) · `background`(1920×1080 불투명). `prompt`는 영문으로 **포즈·사물만** 쓴다(화풍·색은 도구가 붙인다).
- 6장 이상이면 실제 장에 쓰는 마스코트 원화·포즈가 **3개 이상**이어야 하며 **4개 이상**을 권장한다. 마스코트가 나오는 장은 전체의 **30% 이상**, 마스코트·스티커·장면 그림이 나오는 장은 **40% 이상**이어야 한다. `sticker` 또는 `scene`도 하나 이상 실제 장에서 쓴다. 목록에만 적은 그림, 배경, 그래프·도형·표는 이 비율에서 세지 않는다. 5장 이하는 이 오류 기준에서 면제다. 포즈는 그 장에서 하는 일과 맞춘다(발문 → 생각하는 포즈, 활동 → 준비물을 든 포즈, 정리 → 기뻐하는 포즈).
- `mascot.yes`·`mascot.no`를 쓰면 확인 구도에서 맞았을 때·틀렸을 때 그림이 바뀐다(둘 다 쓴다).
- `show`처럼 큰 그림에는 내용에 맞춰 `scene`이나 `sticker`를 고른다. 둘 다 투명 여백을 다듬어 긴 변 최대 800px로 줄이므로 표시 크기에서 흐리지 않은지 확인한다.
- 그림 안에 글자를 넣지 않는다. 꼭 필요하면 `"text": "넣을 글자"`.
- **수학 도형·그래프는 에셋이 아니다.** 구도의 `draw`(직접 그린 SVG)나 `graph` 구도를 쓴다.

## 5. 조작 탐구(`lab`)와 그래프(`graph`)

값은 `state`에, 조절기는 `controls`에, 따라 바뀌는 것은 식으로 적는다. 식은 JS 식이고 `sqrt` `atan2` `max` `PI` 같은 `Math`의 이름을 그대로 쓴다.

```json
{ "id": "lab", "layout": "lab", "title": "막대 **길이를** 바꿔 보자", "tag": "직접 해 보기",
  "purpose": "막대 길이를 바꾸며 삼각형이 되는지 관찰한다", "focus": "움직이는 막대",
  "state": { "a": 6 },
  "controls": [ { "label": "가장 긴 막대", "var": "a", "min": 5, "max": 9, "step": 0.5, "value": 6, "unit": "cm" } ],
  "readouts": [ "나머지 두 막대 3 + 4 = 7", "{a} 와 7 을 견줘요" ],
  "status": [ { "if": "a < 7", "text": "삼각형이 된다!", "tone": "yes" },
              { "if": "a == 7", "text": "딱 붙어 일직선", "tone": "" },
              { "if": "a > 7", "text": "닿지 않는다", "tone": "no" } ],
  "stage": "<svg viewBox=\"0 0 900 640\" role=\"img\" aria-label=\"길이가 3, 4, a인 막대\"><line class=\"rod c-coral\" x1=\"90\" y1=\"150\" x2=\"330\" y2=\"150\"/><line class=\"rod c-sky\" x1=\"90\" y1=\"300\" x2=\"410\" y2=\"300\"/><line class=\"rod c-yellow\" x1=\"90\" y1=\"450\" x2=\"570\" y2=\"450\" data-bind=\"x2:90+80*a\"/></svg>",
  "mascot": "mascot_think" }
```

- `stage`는 SVG 한 개다. 움직일 요소에 `data-bind="속성: 식; 속성2: 식"`을 쓴다(`x2:90+80*a`, `transform:'rotate('+각+' 90 476)'`). 글자는 `<tspan data-show="a">6</tspan>`. 축척(예: 1cm = 80px)을 정하고 **좌표는 계산해서** 쓴다. 조절기의 최솟값·최댓값에서 그림이 칸을 넘지 않게 `viewBox`를 잡는다. 막대·라벨 같은 그리기 클래스는 [수학 표기와 도형](수학-표기와-도형.md).
- `status`의 `if`는 서로 겹치지 않게, 모든 값에서 하나만 참이 되게 쓴다. `tone`은 `yes`(초록)·`no`(붉은)·빈 값.
- `value`는 `state`의 처음 값과 같게.

```json
{ "id": "graph", "layout": "graph", "title": "*a*가 **커지면** 그래프는?", "tag": "탐구 2",
  "purpose": "a를 바꾸며 그래프의 폭이 어떻게 달라지는지 본다", "focus": "움직이는 곡선",
  "state": { "a": 2 },
  "graph": { "x": [-5, 5], "y": [-2, 8] },
  "curves": [ { "fn": "x*x", "tone": "ink", "dashed": true }, { "fn": "a*x*x" } ],
  "points": [ { "at": "1, a", "tone": "sky" } ],
  "controls": [ { "label": "*a*", "var": "a", "min": 0.5, "max": 4, "step": 0.5, "value": 2 } ],
  "formula": "$y = \\val{a}x^2$", "hint": "슬라이더를 움직여 보세요" }
```

- 모눈·축·눈금 숫자·원점 O·축 이름은 엔진이 그린다. `graph`에 범위만 주면 두 축의 한 칸 길이를 같게 하여 가운데에 놓는다. `"equal": false`로 끄거나 `"grid": 1`, `"ticks": 2`, `"labels": ["x","y"]` 등을 지정할 수 있다. 좌표를 px로 계산하지 않는다.
- `curves[].fn`은 *x*의 식, `points[].at`은 `"x식, y식"`. 점을 끌게 하려면 `"drag": "p, q"`(끌면 바뀔 상태 이름 둘)와 `"snap": 0.5`. 조절기·읽기 칸의 개수와 글자 한도는 `layouts lab,graph`로 확인한다.
- 눈금 숫자·축 이름·원점의 기본 크기는 캔버스 기준 32px 이상이다. 학생이 읽는 글자(문장, 그래프의 눈금·축 이름 포함)는 32px 이상, 쪽 번호·저작 표시 같은 보조 글자는 26px 이상으로 둔다. `ticks`를 생략하고 눈금이 촘촘하면 글자를 줄이지 않고 숫자만 일부 건너뛰며 모눈은 그대로다. `ticks`를 직접 주면 그 간격을 따른다.

## 6. `plan`이 알려 주는 것

**오류(고쳐야 넘어간다):** 필수 필드 없음 · 모르는 구도·필드 · id 중복 · 없는 에셋 · 글자 한도 초과 · 목록 개수 범위 밖 · 수식 변환 실패 · 예시(`example-…`)가 남음 · 첫 장이 표지가 아님 · 마지막 장이 정리 구도가 아님 · 마스코트·말풍선 자리가 없는 구도에 `mascot`·`say` · 없는 색 묶음. 6장 이상이면 실제로 쓴 마스코트 그림 3개 미만(`mascot-count`) · 마스코트가 든 장 30% 미만(`mascot-coverage`) · 쓴 스티커·장면 0개(`non-mascot-visual`) · 이미지 모델 그림이 든 장 40% 미만(`image-coverage`) · 그림 없는 장 4장 연속(`no-visual-repeat`)도 오류다.

**경고(까닭 없이 남기지 않는다):** 같은 구도 3장 연속 · 그림 없는 장 2장 연속(`no-visual-repeat`, 직접 그린 시각 자료도 그림으로 셈) · 상호작용 사이 5장 초과 · 상호작용이 한 가지뿐 · 마스코트 그림 4개 미만(`mascot-variety`) · 쓰지 않는 에셋 · `purpose`가 8자 미만이거나 `focus`가 2자 미만 또는 목적과 같음 · 대사 한 줄의 폭이 18자 초과 · 에셋 40개 초과 · 8장 미만 또는 24장 초과. 5장 이하에서는 마스코트가 30% 미만이어도 `mascot-variety` 경고가 난다. 대사 자체의 구도별 한도는 별도로 오류가 될 수 있다.

전체 견본은 `<스킬>/examples/부품-견본/콘티.json`(29구도를 모두 쓴 덱)에 있다. 구도 하나의 쓰임이 궁금하면 거기서 그 구도의 장을 찾아본다.
